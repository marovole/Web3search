## 核心原则

### 1. 明确性（Clarity）

**原则**：Prompt应清晰、具体、无歧义

**好的示例**：
```
分析BTC的价格趋势，包括：
1. 当前价格和24h变化
2. 主要技术指标（RSI、MACD）
3. 支撑阻力位
4. 短期展望（1-7天）
```

**差的示例**：
```
告诉我BTC的情况
```

**改进技巧**：
- 使用具体的问题代替开放式请求
- 明确指定所需的信息维度
- 使用数字列表组织要求

---

### 2. 上下文（Context）

**原则**：提供充足的背景信息，帮助AI理解意图

**好的示例**：
```
你是专业的加密货币分析师。用户是初学者投资者，需要通俗易懂的分析。

当前市场环境：
- BTC价格：$45,000
- 24h变化：+5.2%
- 市场情绪：谨慎乐观

请分析BTC投资机会。
```

**差的示例**：
```
分析BTC
```

**改进技巧**：
- 定义角色和专业领域
- 说明目标受众
- 提供相关数据和市场背景

---

### 3. 结构化（Structure）

**原则**：使用清晰的结构组织prompt

**推荐模板**：
```markdown
## 角色定位
[定义AI的角色和专业背景]

## 输入数据
[提供必要的数据和上下文]

## 分析要求
[列出具体的分析维度]

## 输出格式
[指定输出的结构和格式]

## 约束条件
[明确限制和注意事项]
```

---

### 4. Few-Shot学习

**原则**：提供示例帮助AI理解期望的输出

**示例**：
```markdown
以下是优秀分析的示例：

示例1：
输入：ETH的RSI指标如何？
输出：
当前ETH的RSI为65，处于中性偏强区域。
- **信号**：尚未进入超买（>70），仍有上涨空间
- **建议**：可考虑逢低买入，但需设置止损
- **风险**：若RSI突破70，需警惕回调

现在请用类似方式分析[您的查询]
```

## 优化技巧

### 技巧1：使用思维链（Chain-of-Thought）

**作用**：引导AI逐步推理，提高复杂问题的准确性

**示例**：
```markdown
请按照以下步骤分析：

1. **数据收集**：识别关键指标
2. **趋势分析**：判断多空方向
3. **风险评估**：识别潜在风险
4. **结论综合**：给出最终建议

请逐步展示每个步骤的思考过程。
```

**效果**：准确率提升15-25%

---

### 技巧2：角色扮演（Role-Playing）

**作用**：通过角色定位提高回答的专业性

**示例**：
```markdown
你是一位有10年经验的加密货币分析师，曾成功预测多次牛熊转换。
你的分析风格客观中立，注重风险提示。

请以这种专业视角分析...
```

**效果**：专业度提升20-30%

---

### 技巧3：约束条件（Constraints）

**作用**：通过约束引导输出符合要求

**推荐约束**：
- **长度**：200-400字（简洁有力）
- **格式**：使用Markdown，包含标题和列表
- **数据**：必须引用具体数字和指标
- **免责**：包含"不构成投资建议"声明

**示例**：
```markdown
## 输出要求
- 字数：200-400字
- 格式：Markdown，使用##标题和-列表
- 数据引用：至少3个具体指标
- 风险提示：必须包含
```

---

### 技巧4：反面示例（Negative Examples）

**作用**：明确告诉AI不要做什么

**示例**：
```markdown
## 避免的行为
❌ 不要使用"一定会涨"等绝对预测
❌ 不要忽视风险，过度乐观
❌ 不要使用专业术语而不解释
✅ 应该客观分析，强调不确定性
✅ 应该明确风险因素
✅ 应该通俗易懂
```

---

### 技巧5：分阶段Prompt

**作用**：将复杂任务分解为多个阶段

**Deep Research示例**：
```markdown
## 阶段1：数据收集（5分钟）
收集价格、市值、交易量、社交数据

## 阶段2：定量分析（10分钟）
技术分析、链上分析、流动性分析

## 阶段3：定性分析（10分钟）
项目愿景、团队背景、竞争格局

## 阶段4：风险评估（5分钟）
识别并量化各类风险

## 阶段5：综合结论（5分钟）
形成最终报告
```

## 评估方法

### 自动化评估

使用我们的评估系统：

```python
from app.services.prompt_evaluator import prompt_evaluator

# 评估单个prompt
result = prompt_evaluator.evaluate(
    reference="标准答案",
    hypothesis="AI生成的答案"
)

print(f"BLEU: {result.bleu_score.score:.3f}")
print(f"ROUGE: {result.rouge_scores.score:.3f}")
print(f"Semantic: {result.semantic_score.score:.3f}")
print(f"Overall: {result.overall_score:.3f}")
```

### 人工评估维度

1. **准确性（Accuracy）**：事实是否正确？数据是否准确？
2. **完整性（Completeness）**：是否覆盖所有要求的方面？
3. **相关性（Relevance）**：是否紧扣用户查询？
4. **可读性（Readability）**：是否清晰易懂？
5. **专业性（Professionalism）**：是否体现专业水准？

**评分标准**：
- 5分：完美，所有维度优秀
- 4分：优秀，略有瑕疵
- 3分：良好，满足基本要求
- 2分：及格，有明显不足
- 1分：不合格，需重写

## 常见问题

### Q1：Prompt太长会影响性能吗？

**A**：是的。建议：
- Quick Chat：保持在500 tokens以内
- Deep Research：保持在1500 tokens以内
- 使用模板变量，动态注入数据
- 移除冗余内容

### Q2：如何平衡简洁性和详细性？

**A**：根据场景选择：
- **Quick Chat**：简洁优先（200-400字输出）
- **Deep Research**：详细优先（1000-2000字输出）
- 使用分层结构：核心观点+详细论述

### Q3：中文还是英文prompt更好？

**A**：取决于模型：
- OpenRouter模型：英文通常更准确
- 多语言模型：中文也可以
- **建议**：关键指令用英文，内容用中文

### Q4：如何处理API限流？

**A**：优化策略：
- 使用缓存避免重复查询
- 合并相似查询
- 实现请求队列
- 降级到简化prompt

## 案例研究

### 案例1：Quick Chat优化

**原始Prompt（得分2.5/5）**：
```
分析BTC
```

**问题**：
- 过于简单，缺乏上下文
- 没有指定分析维度
- 没有输出格式要求

**优化后（得分4.5/5）**：
```markdown
你是专业加密货币分析师。分析BTC当前情况：

## 当前数据
- 价格：$45,000
- 24h变化：+5.2%
- 市值：$900B

## 分析要求
1. 趋势判断（多/空/震荡）
2. 关键技术指标
3. 短期展望
4. 风险提示

## 输出格式
- 200-400字
- Markdown格式
- 包含数据来源
```

**改进效果**：
- 准确性：+35%
- 完整性：+50%
- 可读性：+40%

---

### 案例2：Few-Shot优化

**原始Prompt（得分3.0/5）**：
```
分析ETH的RSI指标
```

**优化后（得分4.7/5）**：
```markdown
参考以下示例格式：

示例：
查询：BTC的RSI如何？
回答：
BTC当前RSI为58，处于中性区域。
- 信号：未超买也未超卖，市场平衡
- 建议：可等待更明确信号
- 风险：需关注是否突破50支撑

现在请用相同格式分析ETH的RSI。

当前ETH数据：
- 价格：$2,500
- RSI：67
```

**改进效果**：
- 格式一致性：+60%
- 专业性：+45%
- 可操作性：+50%

## 清单

### Prompt编写清单

**基础要素**（必须）
- [ ] 定义清晰的角色
- [ ] 提供必要的上下文
- [ ] 明确输出要求
- [ ] 包含风险提示

**优化要素**（推荐）
- [ ] 使用Few-shot示例（2-3个）
- [ ] 添加思维链引导
- [ ] 指定输出格式（Markdown）
- [ ] 设置长度约束
- [ ] 提供数据来源要求

**高级要素**（可选）
- [ ] 分阶段任务分解
- [ ] 反面示例说明
- [ ] 条件渲染支持
- [ ] 模板继承复用

### 评估清单

**自动评估**
- [ ] BLEU得分 > 0.4
- [ ] ROUGE得分 > 0.5
- [ ] 语义相似度 > 0.7
- [ ] 综合得分 > 0.6

**人工评估**
- [ ] 准确性 ≥ 4/5
- [ ] 完整性 ≥ 4/5
- [ ] 相关性 ≥ 4/5
- [ ] 可读性 ≥ 4/5
- [ ] 专业性 ≥ 4/5

### A/B测试清单

**测试准备**
- [ ] 样本量 ≥ 30（每组）
- [ ] 流量分配设置（50/50或70/30）
- [ ] 定义成功指标
- [ ] 设置显著性水平（通常0.05）

**结果分析**
- [ ] p-value < 0.05（显著）
- [ ] 效应量 > 0.5（中等效应）
- [ ] 一致性检查（多次测试）
- [ ] 业务影响评估
