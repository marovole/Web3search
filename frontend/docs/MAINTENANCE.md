## 监控系统健康检查

### 1. GA4 健康检查

#### 检查项

```bash
# 1. 检查环境变量
echo $VITE_GA_MEASUREMENT_ID

# 2. 检查数据收集
# 访问 GA4 控制台 → 实时报告
# 应该看到当前用户活动

# 3. 检查事件追踪
# 在应用中执行操作，查看实时事件
```

#### 健康指标

- ✅ 实时数据正常显示
- ✅ 事件正常记录
- ✅ 无数据缺失时段
- ✅ 响应时间正常

#### 异常处理

| 问题 | 原因 | 处理 |
|------|------|------|
| 数据缺失 | 脚本未加载 | 检查 CSP 和网络 |
| 事件未记录 | 用户未同意 | 检查同意状态 |
| 数据延迟 | 正常延迟 | 等待 24-48 小时 |

```bash
# 应该看到最新的错误

# 3. 检查性能数据
# 访问 Sentry Dashboard → Performance
# 应该看到性能指标
```

#### 健康指标

- ✅ 错误正常上报
- ✅ 性能数据正常
- ✅ 无配额耗尽
- ✅ 响应时间正常

#### 异常处理

| 问题 | 原因 | 处理 |
|------|------|------|
| 错误未上报 | DSN 错误 | 检查环境变量 |
| 配额耗尽 | 采样率过高 | 降低采样率 |
| 数据缺失 | 配置错误 | 检查配置 |

## 安全策略更新流程

### 1. CSP 策略更新

#### 更新步骤

1. **识别需求**
   - 分析 CSP 违规报告
   - 识别需要添加的源

2. **更新策略**
   ```javascript
   // 修改 CSP 配置
   const updatedCSP = {
     'script-src': ["'self'", "https://new-source.com"],
     // ...
   }
   ```

3. **测试验证**
   - 在开发环境测试
   - 检查违规报告
   - 验证功能正常

4. **渐进部署**
   - 先使用 report-only 模式
   - 监控违规情况
   - 切换到 enforce 模式

5. **文档更新**
   - 更新配置文档
   - 记录变更原因

---

## 告警规则调整指南

### 1. 调整性能告警

#### 当前规则

```typescript
{
  name: '页面加载时间过长',
  condition: {
    metric: 'page_load_time',
    operator: 'gt',
    threshold: 3000 // 3秒
  }
}
```

#### 调整场景

- **阈值过高**: 降低阈值提高敏感度
- **阈值过低**: 提高阈值减少噪音
- **告警过多**: 增加冷却时间

#### 调整步骤

1. 分析历史数据
2. 确定合理阈值
3. 更新告警规则
4. 测试验证
5. 监控效果

---

### 2. 调整错误率告警

#### 当前规则

```typescript
{
  name: '错误率过高',
  condition: {
    metric: 'error_rate',
    operator: 'gt',
    threshold: 0.05 // 5%
  }
}
```

#### 调整建议

- **生产环境**: 5% 错误率
- **开发环境**: 可适当提高
- **特殊功能**: 根据重要性调整

---

### 3. 添加新告警规则

#### 步骤

1. **定义指标**
   ```typescript
   {
     name: 'API 响应时间',
     metric: 'api_response_time',
     unit: 'ms'
   }
   ```

2. **设置规则**
   ```typescript
   {
     name: 'API 响应慢',
     condition: {
       metric: 'api_response_time',
       operator: 'gt',
       threshold: 2000
     }
   }
   ```

3. **配置通知**
   ```typescript
   {
     channels: ['slack', 'email'],
     severity: 'high'
   }
   ```

4. **测试验证**
   - 触发告警条件
   - 验证通知发送

## 依赖更新和升级流程

### 1. 安全更新

#### 自动更新

```bash
# 运行安全审计
npm audit

# 自动修复
npm audit fix
```

#### 手动更新

```bash
# 检查过时包
npm outdated

# 更新特定包
npm update package-name

# 更新主要版本（谨慎）
npm install package-name@latest
```

---

### 2. 功能更新

#### 更新步骤

1. **检查更新日志**
   - 查看 CHANGELOG
   - 检查 Breaking Changes

2. **测试更新**
   ```bash
   # 创建测试分支
   git checkout -b update-dependencies

   # 更新依赖
   npm update

   # 运行测试
   npm test

   # 检查构建
   npm run build
   ```

3. **代码审查**
   - 审查变更
   - 检查兼容性

4. **部署更新**
   - 合并到主分支
   - 部署到生产环境

---

### 3. 重大版本升级

#### 升级步骤

1. **准备工作**
   - 阅读迁移指南
   - 备份当前代码
   - 创建功能分支

2. **逐步升级**
   ```bash
   # 升级到中间版本
   npm install package-name@next-version

   # 测试兼容性
   npm test

   # 修复问题
   # ...

   # 升级到目标版本
   npm install package-name@target-version
   ```

3. **全面测试**
   - 单元测试
   - 集成测试
   - E2E 测试

4. **部署验证**
   - 部署到预发布环境

## 应急响应

### 发现安全漏洞

1. **立即评估**
   - 确定漏洞严重性
   - 评估影响范围

2. **临时修复**
   - 应用临时缓解措施
   - 禁用受影响功能（如需要）

3. **永久修复**
   - 更新依赖或修复代码
   - 全面测试验证

4. **部署修复**
   - 紧急部署到生产环境
   - 监控修复效果

---

### 监控系统故障

1. **故障诊断**
   - 检查环境变量
   - 检查网络连接
   - 查看错误日志

2. **恢复服务**
   - 修复配置问题
   - 重启服务（如需要）
   - 验证功能恢复

3. **数据恢复**
   - 检查数据完整性
   - 恢复丢失数据（如可能）
